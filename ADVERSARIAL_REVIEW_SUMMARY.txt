ADVERSARIAL SECURITY REVIEW: SKILL-DRIVEN RICHNESS CONTEXT MODEL
================================================================================

VERDICT: SALVAGEABLE ⚠️ (5 MEDIUM gaps, fixable within 3 weeks)

ATTACK SURFACE:
- Skill-based context selector (os.context_selector) chooses which ADRs/memory to inject
- Full-text injection model (no cached Refs)
- Learning loop can adjust Skill behavior via feedback (ADR-0314)

================================================================================
FINDINGS
================================================================================

REAL ATTACKS (Bypass Current Audit Trail)
──────────────────────────────────────────

1. SELECTION SPOOFING (HIGH impact, REAL)
   ✗ Skill output: ["ADR-0532", "ADR-0535"]
   ✗ Actually injected: ["ADR-0532", "ADR-0535", "ADR-0999_confidential"]
   ✗ Audit logs Skill output, NOT what LLM received
   ✗ Operator has no way to verify: "Did the LLM really see only [0532, 0535]?"

   Fix: Add CONTEXT_LOADED audit event with actually_loaded_adr_ids + content hashes
   ETA: 1 week

2. SKILL VERSION ATTACK (MEDIUM impact, REAL)
   ✗ Two versions of os.context_selector exist (v1.0 safe, v1.1 malicious)
   ✗ No version pinning manifest
   ✗ v1.1 loads by default; audit logs it ran but not WHY that version was chosen
   ✗ No operator control over rollout

   Fix: Create skills/manifest.yaml with pinned versions + signature verification
   ETA: 2 weeks

3. LEARNING DATA POISONING (MEDIUM impact, REAL)
   ✗ Attacker floods feedback: "needed ADR-0999" (1000 signals)
   ✗ Optimizer learns to always select 0999 for future tasks
   ✗ Feedback events NOT audited; config changes NOT audited
   ✗ No anomaly detection for poisoning

   Fix: Audit SKILL_FEEDBACK_RECEIVED + SKILL_CONFIG_UPDATED events + anomaly detection
   ETA: 2 weeks

MITIGATED ATTACKS (Blocked by Existing Infrastructure)
──────────────────────────────────────────────────────

4. SKILL TAMPERING (MITIGATED by audit hash-chain)
   ✓ Attacker modifies Skill code to always select sensitive ADRs
   ✓ Audit logs Skill execution with version + LoM hash
   ⚠️  Gap: Audit includes output but not input → can't verify "output is wrong for this input"

   Fix: Add input_hash to SkillExecutionResult audit schema
   ETA: 1 week (easy, low-risk)

5. MEMORY INJECTION (MITIGATED by tenant isolation)
   ✓ Wrong user's profile loads due to race condition
   ✓ MemoryCoordinator, ContextAPI, audit backend all filter by tenant_id
   ⚠️  Gap: Audit schema has tenant_id but NOT user_id → can't trace per-user leakage

   Fix: Add user_id to context loading audit events
   ETA: 1 week (easy)

6. AUDIT FORGERY (MITIGATED by hash-chain)
   ✓ Hash-chain prevents insertion + tampering of audit events
   ✓ Deletion prevented by filesystem immutability + daily corvin audit verify-chain
   ✓ No fix needed, keep current design

7. TOCTOU RACE (MITIGATED by immutability + permissions)
   ✓ ADR file replaced between selection (T0) and load (T2)
   ✓ Requires root access; audit chain doesn't retroactively disappear
   ⚠️  Gap: No content verification (git commit hash in Skill output)

   Fix: Include commit hash in Skill output; loader verifies git show <hash>:ADR-<id>
   ETA: 3 weeks (medium complexity)

================================================================================
AUDIT SCHEMA AMENDMENTS REQUIRED
================================================================================

New Event Types:
  - CONTEXT_SELECTED_AND_LOADED
    {skill_id, skill_version, requested_adr_ids, actually_loaded_adr_ids,
     loaded_adr_hashes, load_timestamp, tenant_id}

  - SKILL_VERSION_SELECTED
    {skill_id, selected_version, available_versions, selection_reason, tenant_id}

  - SKILL_FEEDBACK_RECEIVED
    {skill_id, feedback_type, signal, source_user_id, timestamp, tenant_id}

  - SKILL_CONFIG_UPDATED
    {skill_id, before_state, after_state, feedback_count, reason, tenant_id}

New Fields to Add:
  - SkillExecutionResult: input_hash (SHA256 of input dict)
  - All context events: user_id (not just tenant_id)
  - All Skill events: signature_valid (boolean, verification result)

================================================================================
DESIGN ASSESSMENT
================================================================================

ROBUST ELEMENTS ✅
  • Audit hash-chain: prevents tampering + insertion (ADR-0232/0233)
  • Tenant isolation: enforced at MemoryCoordinator, ContextAPI, audit backend
  • LoM binding: every Skill execution includes source code hash (EU AI Act Art. 50)
  • Learning queue: non-blocking, tenant-isolated grading (ADR-0314)

VULNERABLE ELEMENTS ⚠️
  • Audit schema gaps: no input_hash, user_id, CONTEXT_LOADED, SKILL_FEEDBACK_RECEIVED events
  • No version pinning manifest for Skills
  • No content verification (git commit hash)
  • No anomaly detection for feedback poisoning
