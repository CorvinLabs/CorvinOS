FIX M1: REGISTRY LOAD FAIL-CLOSED
─────────────────────────────────
Issue: load_registry() silently treated unparseable or wrong-shaped registry
       files as empty, then save_registry() would overwrite them with empty
       data → COMPLETE DATA LOSS

Root Cause: Exception handling too broad, silent reset on any error

Fix Applied:
  1. Unreadable YAML → raises ValueError (fail-closed)
  2. Wrong shape (not a mapping) → raises ValueError
  3. List-shaped "plugins" field → raises ValueError
  4. Only missing files are treated as empty
  5. All validation explicit and documented

FIX M2: PATH TRAVERSAL IN UNINSTALL
───────────────────────────────────
Issue: 'corvin plugin uninstall ../../x' or similar traversal ids could
       delete directories outside the tenant directory

Root Cause: No validation of plugin_id before using it in path operations

Fix Applied: _safe_installed_dest() with DUAL INDEPENDENT GUARDS
  1. Guard 1: validate_plugin_id() — allowlist charset rejects .. / \
  2. Guard 2: Resolved containment — even slipped id cannot escape tenant
  
  Defense in depth: if one guard fails, the other stops the attack

Code Location: core/plugins/corvin_plugins/tenant_plugins.py lines 122-141
def _safe_installed_dest(self, plugin_id: str) -> Path:
    from .manifest import validate_plugin_id
    validate_plugin_id(plugin_id)  # GUARD 1: charset allowlist
    
    root = self.installed_dir
    candidate = root / plugin_id
    resolved_root = root.resolve(strict=False)
    resolved = candidate.resolve(strict=False)
    
    # GUARD 2: resolved containment check
    if resolved != resolved_root and resolved_root not in resolved.parents:
        raise ValueError(f"plugin_id {plugin_id!r} resolves outside tenant")
    return candidate

Used in:
  - register_plugin() → dest = self._safe_installed_dest(plugin_id)
  - unregister_plugin() → dest = self._safe_installed_dest(plugin_id)
  - get_plugin_path() → path = self._safe_installed_dest(plugin_id)

FIX 2.1: TARBALL PATH TRAVERSAL
────────────────────────────────
Issue: tar.extractall() without security filter could extract files with
       ../../../etc/passwd paths, escaping the temporary directory

Root Cause: No PEP 706 filter applied to tar.extractall()

Fix Applied: tar.extractall(path=temp_dir, filter="data")
  PEP 706 standard filter rejects:
  - Absolute paths (/etc/passwd)
  - Traversal paths (../../../etc/passwd)  
  - Symlinks (can point outside)
  - Device files (/dev/null, /dev/zero)

    tar_bytes = BytesIO(tarball_data)

        # filter="data" (PEP 706) rejects absolute paths, ".." traversal,

def _extract_and_verify_manifest(...) -> tuple[dict, Path, Path] | None:
    """Returns (manifest_dict, plugin_dir_path, temp_dir).
    temp_dir is the CALLER-OWNED root to delete — the caller must NOT guess
    it from plugin_dir.parent (when plugin.yaml sits at tarball root,
    plugin_dir == temp_dir and .parent is the SYSTEM temp root, so rmtree
    would wipe /tmp).
    """
    temp_dir = Path(tempfile.mkdtemp())  # Explicit owner
    ...extract tarball...
    plugin_dir = manifest_path.parent  # May == temp_dir if at root
    return manifest_data, plugin_dir, temp_dir  # All explicit

Defense:
  - temp_dir explicitly tracked and returned
  - Caller guaranteed by signature to use returned temp_dir
  - Never infers cleanup path from plugin_dir.parent
  - If extraction places plugin.yaml at root: plugin_dir == temp_dir (safe)
  - If nested: plugin_dir is child of temp_dir (safe)
