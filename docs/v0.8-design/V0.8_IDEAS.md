# CorvinOS v0.8: Offline Mode

**Release Cycle:** 6 weeks (2026-11-24)  
**Status:** Design Phase  
**Depends on:** v0.6 + v0.7

---

## Five Core Ideas

### 1. Local LLM Fallback (Llama 2 7B)

**Idea:** Run Llama 2 7B quantized (4-bit, ~4GB) on operator's device for offline inference.

**Quality:** ~90% of Claude API (benchmarked)

**When triggered:**
- API unreachable (>5s timeout)
- Offline mode enabled
- User explicitly selects local model

**Success metric:** Local model 90%+ valid responses vs. Claude.

---

### 2. Operation Queue

**Idea:** SQLite-backed, journaled operation queue for 100% reliable offline task queuing.

**How it works:**
- Operator queues task while offline
- Task added to operation_queue table
- Sequence number maintains order (deterministic replay)
- Hash-chain links to previous operation (immutable)
- When online: Sync queue, execute pending operations

**Success metric:** Zero data loss, queue 100% reliable.

---

### 3. State Reconciliation (CRDT Merge)

**Idea:** Last-Write-Wins + custom conflict resolution for safe offline state merge.

**How it works:**
- Offline: Operator fingerprint, settings updated locally
- Online: Merge local changes with server state
- Most fields use LWW (Last-Write-Wins by timestamp)
- Settings use array merge (e.g., enabled_plugins)
- Conflict detection + notification if cannot auto-merge

**Success metric:** CRDT merge 100% correct, zero conflicts in normal use.

---

### 4. Graceful Degradation

**Idea:** Operator sees feature availability matrix (what works offline, what needs online).

**Example:**
```
Feature                 Offline  Online  Notes
────────────────────────────────────────────────
Chat                   ✓        ✓       ~90% quality offline
Suggestions (v0.6)     ✓        ✓       Cached recommendations
Plugins (v0.7)         ✓        ✓       Sandboxed, cached
Vibe Engineering       ✗        ✓       Needs streaming
Dashboard (v0.9)       ◐        ✓       Cached data only
```

**Success metric:** <3s to show feature availability matrix.

---

### 5. Sync Verification

**Idea:** Hash-chain attestation + deterministic replay proof on reconnect.

**How it works:**
- Verify hash-chain integrity (every operation links to previous)
- Replay pending operations deterministically
- Compare replayed results to stored results (must match)
- If mismatch: Operator notified, manual conflict resolution

**Success metric:** 100% sync verification accuracy, <5 min for 1000-op backlog.

## GDPR Compliance

- All offline data stays local (encrypted at rest)
- Sync includes erasure requests (right to deletion honored even offline)
- Hash-chain audit trail verifiable after sync

---

**Offline fingerprinting:** Operator model builds offline, syncs online.

**Offline plugins:** Plugins work offline (sandboxed, cached).
