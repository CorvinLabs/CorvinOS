## Key Features

### 1. Automatic Backup Creation
```
Before each mutation (second save onwards):
  registry.yaml.bak ← copy of previous registry state
  (atomic operation: temp → replace)
```

### 2. Automatic Recovery
```
On load with corrupted registry:
  1. Detect: YAML parse error
  2. Log: corruption_detected event in audit trail
  3. Recover: restore_from_backup()
  4. Verify: new state is valid
  5. Continue: transparent to caller
```

### 3. Fail-Closed Design
```
No backup available?
  → Raise RegistryCorrupt
  → Never return empty registry
  → Never silently corrupt data
  → Operator sees clear error

Both files corrupted?
  → Raise RegistryCorrupt
  → Recommend manual recovery
  → Full audit trail available
```

### 4. Multi-Tenant Isolation
```
Each tenant has:
  ~/.corvin/tenants/<tid>/plugins/registry.yaml
  ~/.corvin/tenants/<tid>/plugins/registry.yaml.bak
  (separate backups, tenant_id in audit trail)
```

### 5. Audit Trail Integration
```
Events recorded:
  - plugin.registry_corruption_detected
  - plugin.registry_corrupted_recovered
  - plugin.installed/enabled/disabled/uninstalled
  
(All hash-chained, GDPR Art. 30/32 compliant)
```

## Technical Summary

**Atomic Write Strategy:**
1. Create backup (if registry exists) → atomic replace
2. Write to temp file → fsync → chmod 0o600
3. Atomic replace (os.replace) — all-or-nothing

**Recovery Strategy:**
1. Detect corruption on load
2. Emit audit event
3. Attempt restore_from_backup()
4. Verify restored state
5. Fail closed if unable to recover

**Concurrency Control:**
- Intra-process: threading.RLock
- Inter-process: fcntl (POSIX) / file lock (Windows)
- Via `registry_mutation()` context manager

**Audit Integration:**
- Hash-chained events via existing `_audit()` function
- No PII leaked (plugin_id only)
- GDPR Art. 30/32 compliant
