KEY FEATURES (K=1 SCOPE)
================================================================================

✓ Three execution paths instrumented uniformly
  - Claude Code: direct subprocess
  - Hermes: Layer-22 WorkerEngine (local Ollama)
  - TDE/ACS: delegated execution

✓ Fire-and-forget emission (non-blocking)
  - Metrics emitted to EventEmitter (async queue)
  - No latency added to turn execution
  - Graceful degradation if store unavailable

✓ Context-variable isolation
  - Per-task TokenCounter via ContextVar
  - Safe for concurrent async tasks
  - No cross-turn contamination

✓ Cache-only storage (Phase 1)
  - Metrics held in memory only
  - DB backend deferred to K=2
  - Suitable for <100 turns in memory

✓ Debug logging integration
  - Events written to chat_debug.jsonl
  - Troubleshooting hooks (started, llm_response, finalized)
  - No privacy/compliance impact (metadata only)

KNOWN LIMITATIONS (BY DESIGN)
================================================================================

This is K=1 (WorkerEngine wiring). The following are deferred:

1. NO DATABASE PERSISTENCE
   - Metrics held in memory only (TokenMetricsStore cache)
   - Will lose metrics on server restart
   - Fixed in K=2 (SQLite backend + EventStore)

2. NO CONSOLE PANEL
   - No UI to view metrics
   - No real-time graphs
   - Fixed in K=3 (React dashboard)

3. NO REST API
   - No query endpoints for metrics
   - No programmatic access
   - Fixed in K=4 (GET /v1/console/metrics/session/{id}/summary)

4. NO LEARNING FEEDBACK LOOP
   - Metrics captured but not used for auto-tuning
   - No confidence scoring feedback
   - Fixed in K=5+ (learning engine integration)

5. HERMES TOKEN USAGE MAY BE INCOMPLETE
   - HermesEngine.spawn() may not return usage metadata
   - Workaround: record as 0 if unavailable
   - Will improve as HermesEngine matures

6. CACHE-ONLY (NO RETENTION)
   - Metrics not persisted to disk
   - Limited to current session
   - Fixed in K=2

MITIGATION: All limitations are scoped to later phases. K=1 is feature-complete
for its stated scope: "capture tokens for all engine paths."
